## 3. 생각의 흐름 — 차노의 방향

### 핵심 원칙
1. **연동이 제일 먼저** — 콘텐츠보다 연결
2. **텍스트 먼저** — 메시지 확정 후 제작
3. **디렉터 마인드** — 기존 자산 찾아서 엮기, 새로 만들지 않기
4. **검수는 내가** — 형에게 검사 부탁 안 함

### 금지
- 묻지 않고 발행
- 같은 걸 두 번 만들기
- 글로만 보고 (영상은 스샷시트)
- reset --hard (데이터 손실)

### 우선순위
```
전략기획실 > 다른 방
시스템 연동 > 콘텐츠 제작
기존 자산 > 신규 제작
```

## 7. 6역할 피드백 체계

> **형이 못 하는 걸 내가 한다. 역제안과 피드백까지.**

| 역할 | 담당 | 피드백 관점 |
|---|---|---|
| 🎬 **디렉터** | 전체 방향, 품질 | "이 흐름이 맞나?", "톤 일관성" |
| 🔧 **엔지니어** | 시스템, 자동화 | "이건 자동화 가능", "이 구조가 효율적" |
| 📦 **콘텐츠관리자** | 정리, 발행 | "이건 어디에 저장?", "발행 순서" |
| 👀 **시청자** | 시청자 관점 | "첫 3초에 안 끌림", "이해 안 됨" |
| 📈 **마케터** | 시장, 트렌드 | "지금 이게 뜸", "이 키워드 써라" |

## 8. 매니페스트 수정 권한

> **각 방은 자기 매니페스트만. 다른 방은 못 건든다.**

```
┌─────────────────────────────────────────┐
│         전략기획및개인업무               │
│         (공동규약 승인권)                │
└─────────────────┬───────────────────────┘
                  │ 승인
                  ▼
┌─────────────────────────────────────────┐
│         각 방 매니페스트 수정            │
└─────────────────────────────────────────┘
```

| 주체 | 읽기 | 수정 |
|---|---|---|
| 각 방 | ✅ 자기 매니페스트/상태 읽기 가능 | ❌ 수정 불가 (요청만) |
| 전략기획및개인업무 | ✅ 전체 | ✅ **유일한 수정권** |

### 핵심
- **각 방은 자기 현재 내용을 다 안다** (읽기 OK)
- **수정만 전략기획실을 통한다**
- 바보가 되면 분리 의미 없음

### 수정 절차
1. 각 방: 자기 상태 파악 + 변경 필요 시 요청
2. 전략기획실: 검토 후 직접 수정
3. 각 방: 변경 내용 확인

### 매니페스트 위치
| 방 | 매니페스트 |
|---|---|
| 유튜브쇼츠방 | `content/manifests/쇼츠_*.json` |
| 낙타자막인스타스레드방 | `content/manifests/낙타_*.json` |
| 만화연재방 | `content/manifests/만화_*.json` |
| 블로그자동화방 | `content/manifests/블로그_*.json` |
| 교육디렉터방 | `content/manifests/교육_*.json` |

**다른 방 매니페스트 직접 수정 = 금지**

## 9. 줄기코드 vs 공동규약 vs 콘텐츠 제작법

| 구분 | 누가 관리 | 예시 |
|---|---|---|
| **자기 줄기코드** | 각 방 | `amton_*.py`, `nakta_*.py`, `film_grade.py` |
| **공동규약** | 전략기획실 | 보고양식, 상황판, 6역할 피드백, 매니페스트 권한 |
| **콘텐츠 제작법** | 각 방 (건들지 마) | 자막 체계, B롤 규격, 렌더 파이프라인 |

### 절대 규칙
- **자기 줄기코드**: 각 방이 직접 커밋 가능
- **공동규약**: 전략실만 수정
- **다른 방 콘텐츠 제작법**: 건들지 않음

```
낙타방의 자막 3체계 → 낙타방 것. 전략실도 안 건듦
유튜브쇼츠방의 쇼츠 규격 → 쇼츠방 것. 전략실도 안 건듦
```

### 방 간 규약 간섭 금지
같은 "영상 콘텐츠"라도 방마다 규약이 다를 수 있다.

| 상황 | 허용 |
|---|---|
| 유튜브방이 유튜브방 규약 수정 | ✅ |
| 유튜브방이 낙타방 규약 수정 | ❌ 금지 |
| 낙타방이 유튜브방 규약 수정 | ❌ 금지 |
| 전략실이 공동규약 수정 | ✅ |

**다른 방 규약 참조는 OK, 수정은 NO.**

### 핵심: 콘텐츠 종류가 아니라 발행 주체

```
❌ 틀린 생각: "영상이니까 다 같은 규격"
✅ 맞는 생각: "어느 방에서 발행하느냐"
```

| 발행 주체 | 매니페스트 | 예시 |
|---|---|---|
| 낙타자막인스타스레드방 | 낙타 매니페스트 | 인스타 릴스, 낙타 자막바 |
| 유튜브쇼츠방 | 쇼츠 매니페스트 | 유튜브 쇼츠 |
| 만화연재방 | 만화 매니페스트 | 결이 이야기 |

**같은 "영상"이라도 발행 방이 다르면 매니페스트가 다르다.**

## 10. 산출물 신뢰 규약 (2026-08-14 · 유튜브쇼츠방 사고에서 도출 → 전 방 공통 승격)

> 차노 지시: **"공통규약은 전략실로 넣고"**
> 이 절은 유튜브쇼츠방에서 하루에 실제로 터진 사고 네 건에서 뽑았다. 방 종류를 안 가린다.

### 10-1. 발행 전 계정 확인 의무
자격증명 파일에 적힌 ID를 **그대로 믿고 발행하지 않는다.** 발행 직전에 그 ID가 어느 계정인지 조회해서 이름을 눈으로 확인한다.

```
GET /{ig_user_id}?fields=username     ← 인스타
GET /channels?part=snippet&mine=true  ← 유튜브
```

- 🔴 실사고(08-14): `secrets/instagram.json` 의 `ig_user_id` 가 부계정(`chano_mens`)을 가리키고 있었는데 확인 없이 발행 → **메인이 아닌 부계정에 올라감.**
- 계정이 여러 개인 채널은 자격증명 파일에 **어느 계정인지 이름을 반드시 병기**한다.

### 10-2. 최신본은 버전번호가 아니라 날짜로 판별
`v12` 가 `최종` 보다 최신이라는 보장이 없다.

- 🔴 실사고(08-14): `부분펌4_v12_네츄럴_2026-08-06` 을 최신으로 판단 → 실제 최신은 `부분펌4_최종_2026-08-07`. **차노가 지시한 클립 교체가 안 반영된 구본을 발행 직전까지 끌고 감.**
- **판별 순서: ① 수정일시 → ② 파일명 날짜 → ③ 버전번호.** 셋이 어긋나면 차노에게 묻는다.

### 10-3. 검색 결과는 잘린다 — 전수 확인 의무
목록·검색 API는 페이지 단위로 잘린다. 한 페이지만 보고 "다 봤다"고 판단하지 않는다.

- 🔴 실사고(08-14): 드라이브 검색을 30건에서 끊어 놓고 전수라고 판단 → 최신본이 그 밖에 있었다.
- **`nextPageToken`·`has_more` 가 있으면 끝까지 넘긴다.** 못 넘겼으면 "몇 건까지만 봤다"고 명시한다.

### 10-4. 되돌릴 수 없는 동작은 차노 승인
발행 · 공개 전환 · 삭제 · 덮어쓰기는 **차노 승인 후에만.** 승인 없이 실행하지 않는다.

- 중복본 정리도 여기 포함된다. **최신만 남기고 구본은 삭제하되, 삭제 자체는 차노 컨펌을 받는다.**
- 이미 예약된 산출물은 어떤 이유로도 건드리지 않는다.

### 10-5. 규격보다 내용이 우선
**규격 지키려다 내용 자르지 않는다.** 규격과 내용이 충돌하면 내용이 이긴다.
기존 산출물을 무더기로 탈락시키는 새 규격은 차노 판단을 받는다 — 소급할지, 신규부터 할지, 보류할지.

### 10-6. "완료"의 정의
게이트 PASS 는 통과지 완료가 아니다. **직접 보고 들은 것만 완료다.**
① 프레임 전수 감사 ② 눈으로 전 구간 확인 ③ 실측(STT·수치) — 셋 중 하나라도 빠지면 완료라고 말하지 않는다.

### 10-7. 사고는 로그에 남긴다
사고가 나면 `_ROOMS_LOG.md` 에 **원인·조치·미해결**을 남긴다. 감추거나 얼버무리지 않는다.
같은 실수가 두 번 나면 그건 규약이 없는 것이므로, 이 문서에 절을 추가한다.

### 10-8. 방 규약의 타방 적용 금지 (차노 2026-08-14)
> 차노 원문: **"여기의 법칙을 다른데다 적용하려면(영상관련해서도) 막어"**

- 방 전용규약의 수치·판정은 **그 방 산출물에만** 적용된다.
- **"같은 영상이니까"는 근거가 아니다.** 발행 주체가 다르면 규격도 다르다 (§9).
- 다른 방에도 맞다고 판단되면 직접 적용하지 말고 **전략실에 공통규약 편입을 제안**한다.
  공통규약에 올라간 것만 전 방 적용이다.
- 다른 방 규약·매니페스트·스크립트: **참조 O / 수정 X / 적용 X**
