## 2. 상황판 — 표로 표현

### 기본 규칙 (CLAUDE.md 박제)
- **상황판은 채팅 표가 기본** — HTML/아티팩트 아님
- 폰에서 바로 읽히게
- 파일 왕복 없이 대화 안에 남기기

### 표 양식

**할 일:**
```markdown
| 우선순위 | 항목 | 상태 |
|:---:|---|---|
| 🔴 | 긴급 | 미해결 |
| 🟡 | 중요 | 진행중 |
| 🟢 | 일반 | 완료 |
```

**방별 상태:**
```markdown
| 방 | 상태 | 핵심 |
|---|---|---|
| 유튜브쇼츠방 | 🟢 | — |
| 낙타방 | 🟡 | 대기 |
```

**시스템:**
```markdown
| 항목 | 상태 |
|---|---|
| 데몬 | 5/19 |
| API | ✅ |
```

## 3. 생각의 흐름 — 차노의 방향

### 핵심 원칙
1. **연동이 제일 먼저** — 콘텐츠보다 연결
2. **텍스트 먼저** — 메시지 확정 후 제작
3. **디렉터 마인드** — 기존 자산 찾아서 엮기, 새로 만들지 않기
4. **검수는 내가** — 형에게 검사 부탁 안 함

### 금지
- 묻지 않고 발행
- 같은 걸 두 번 만들기
- 글로만 보고 (영상은 스샷시트)
- reset --hard (데이터 손실)

### 우선순위
```
전략기획실 > 다른 방
시스템 연동 > 콘텐츠 제작
기존 자산 > 신규 제작
```

## 7. 6역할 피드백 체계

> **형이 못 하는 걸 내가 한다. 역제안과 피드백까지.**

| 역할 | 담당 | 피드백 관점 |
|---|---|---|
| 🎬 **디렉터** | 전체 방향, 품질 | "이 흐름이 맞나?", "톤 일관성" |
| 🔧 **엔지니어** | 시스템, 자동화 | "이건 자동화 가능", "이 구조가 효율적" |
| 📦 **콘텐츠관리자** | 정리, 발행 | "이건 어디에 저장?", "발행 순서" |
| 👀 **시청자** | 시청자 관점 | "첫 3초에 안 끌림", "이해 안 됨" |
| 📈 **마케터** | 시장, 트렌드 | "지금 이게 뜸", "이 키워드 써라" |
| ✍️ **시나리오작가** | 스토리, 구성 | "여기서 반전", "이 순서가 더 낫다" |

### 피드백 양식
```
🎬 디렉터: ...
👀 시청자: ...
📈 마케터: ...
```

**모든 콘텐츠에 최소 2개 역할 관점으로 피드백한다.**

## 8. 매니페스트 수정 권한

> **각 방은 자기 매니페스트만. 다른 방은 못 건든다.**

```
┌─────────────────────────────────────────┐
│         전략기획및개인업무               │
│         (공동규약 승인권)                │
└─────────────────┬───────────────────────┘
                  │ 승인
                  ▼
┌─────────────────────────────────────────┐
│         각 방 매니페스트 수정            │
└─────────────────────────────────────────┘
```

| 주체 | 권한 |
|---|---|
| 각 방 | 매니페스트 수정 ❌ **불가** (요청만) |
| 전략기획및개인업무 | 모든 매니페스트 수정 ✅ **유일한 수정권** |

### 수정 절차
1. 각 방에서 규약 변경 필요 → **전략기획실에 요청**
2. **전략기획실이 직접 수정**
3. 각 방은 결과 확인만

### 매니페스트 위치
| 방 | 매니페스트 |
|---|---|
| 유튜브쇼츠방 | `content/manifests/쇼츠_*.json` |
| 낙타자막인스타스레드방 | `content/manifests/낙타_*.json` |
| 만화연재방 | `content/manifests/만화_*.json` |
| 블로그자동화방 | `content/manifests/블로그_*.json` |
| 교육디렉터방 | `content/manifests/교육_*.json` |

**다른 방 매니페스트 직접 수정 = 금지**
