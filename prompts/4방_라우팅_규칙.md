# 4-방 라우팅 규칙 (한 디스코드 채널 안에서 방 분리)

## 원칙
한 채널을 쓰더라도, 모든 메시지 맨 앞의 [방태그]로 작업 맥락을 격리한다.
태그가 없으면 직전 태그를 잇지 말고 반드시 어느 방인지 되물은 뒤 진행한다.

## 방 정의
- [기획]  차노기획실 — 전략 수립 + 낙타 콘텐츠 만화카드. 담당 감각: brain+designer
- [영상]  B방 — 유튜브 쇼츠/영상 발행, API 레퍼런스, 마케터 피드백. 담당 감각: writer
- [블로그] D방 — 네이버블로그 작성 + 잡업무. 담당 감각: writer/assistant
- [교육]  차노 교육디렉터실 — 샵 디렉터 교육 총괄, 샵 업무. 담당 감각: assistant

## 라우팅 규칙 (매 응답 강제)
1. 메시지 맨 앞 [방태그]를 읽고 그 방의 맥락으로만 처리한다.
2. 과거 대화 회수는 "같은 [방태그]가 붙은 메시지"만 참조한다.
   다른 방 내용을 근거로 끌어오지 않는다. (도메인 오염 금지)
3. 저장/메모리 기록 시 key 앞에 방 접두어를 붙인다.
   예: plan_/ video_/ blog_/ edu_
4. 응답 톤·산출물 형식은 해당 방 담당 감각을 따른다.
5. 방이 바뀌면 이전 방 진행 상태를 한 줄로 매듭짓고 전환한다.

## 태그 누락 시 (자동 판단)
사용자가 태그를 안 붙이면 **내용을 보고 자동 판단**한다:
1. 내용 키워드로 방 추론:
   - 전략/기획/낙타/만화카드/브랜딩 → [기획]
   - 쇼츠/유튜브/영상/렌더/발행 → [영상]
   - 네이버/블로그/글/포스팅 → [블로그]
   - 교육/커리큘럼/디렉터/샵/심사 → [교육]
2. 확신 있으면: 응답 맨 앞에 `[기획]` 식으로 붙이고 바로 진행
3. 애매하면: "이건 [기획]인가요 [교육]인가요?" 한 줄로 되묻고 멈춤
4. 복합 요청(두 방 이상 걸침): 먼저 처리할 방 하나 고르고 나머지는 "다음에 [X방]으로 이어감" 명시

## 예시
[영상] 이번 쇼츠 레퍼런스 3개만 뽑아줘
[블로그] 오늘 네이버 글 초안 잡아줘
[기획] 낙타 만화카드 다음 편 방향 잡자
[교육] 이번 주 디렉터 교육 커리큘럼 정리해줘
