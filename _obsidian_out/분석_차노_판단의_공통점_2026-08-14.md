## 한 문장

> **사람의 기억과 의지를 믿지 않고, 구조가 대신 기억하게 만든다.**

거의 모든 판단이 **사람에게 달린 단계를 구조에 달린 단계로 바꾸는 방향**이다.

| 사람에게 달렸던 것 | 무엇으로 바꿨나 | 언제 |
|---|---|---|
| 규칙을 기억하기 | 검사코드로 잠그기 | 07-21 |
| 결과물을 다시 만들기 | 생성기를 리포에 박제 | 07-28 |
| 채팅으로 기억하기 | 커밋 = 박제 | 07-20 |
| 매번 정답 물어보기 | 감각 가이드 + 게이트 | 08-04 |
| 같은 지시 반복하기 | 정본 문서 · 재론 금지 | 07-15 |
| 눈으로 검수하기 | 게이트가 자동 검출 | 08-09 |

## 다섯 가지 반복 패턴

### 1. 틀린 것을 고치지 않고, 틀릴 수 있는 자리를 없앤다
- "실수가 게이트를 빠져나가면 → **게이트를 뜯어** 왜 못 잡았는지 분석하고 검사를 추가한다. '실수다'로 넘기면 계속 반복된다." (07-21)
- 자막 겹침을 고치는 게 아니라 `layout_ok` 검사를 만든다.
- **사고 하나 = 새 검사 항목 하나.** 사고가 자산이 된다.

### 2. 배관이 산출물보다 먼저다
- "연동이 콘텐츠보다 먼저다" (최상위 원칙)
- "배수관 먼저, 양동이 나르지 말자"
- "포맷을 얼려놓고 내용만 갈아끼움 — 구조를 매번 재설계하지 말 것"
- → **한 번 빨리 하는 것보다, 다음에도 되는 것**을 택한다.

### 3. 원본에서 시작한다 — 지어내기 금지
- 볼트에 차노 문장이 없는 주제는 **창작 금지**, 방향·구술을 요청.
- 재정의는 **대장에 확정된 단어만.** 없으면 새로 못 박는다.
- "이찬호 문장 창작(흉내) 금지 — 실제 쓴 문장만 인용"
- → 창작은 허용하되 **날조는 금지.** 경계가 '원본이 있느냐'다.

### 4. 추측 금지 — 찍어보고 말한다
- "코드 분기를 읽고 '이럴 것이다' 라고 하지 않는다. **실측 없이 한 말은 보고에 넣지 않는다.**"
- 완료 3조건: 내가 봤다 · 내가 들었다 · 피드백으로 다시 돌렸다.
- → **게이트 PASS는 통과일 뿐 완료가 아니다.**

### 5. 원인을 한 층 아래에서 찾는다
- "무드를 읽나요 — 어색해" → 텍스트 문제로 오해하고 되묻기를 삭제 → **진짜 원인은 TTS 발음 오독.** 텍스트 원복, 발음사전으로 해결.
- 네이버 로그인 세션 유실 → 원인은 `SIGTERM` 핸들러가 `ctx.close()` 없이 종료.
- → **증상을 고치기 전에 층을 한 번 내려간다.**

## 결정의 층위를 나눈다 (이게 핵심 감각)

무엇이든 잠그는 사람이 아니다. **잠글 것과 열어둘 것을 나눈다.**

| 잠근다 (게이트) | 열어둔다 (감각) |
|---|---|
| 해상도 · 길이 · 자막 위치 · 오디오 | 컬러냐 흑백이냐 |
| 안전영역 · 배경 밝기 | 어떤 B롤을 고르냐 |
| 규격 · 정본 · 재정의 단어 | 어떤 각도로 쓰느냐 |

- "**컬러/흑백으로 FAIL 내면 안 된다.** 게이트는 기술규격만 잡는다. 컬러/흑백은 편집 선택이라 pass/fail 대상이 아니다." (08-04)
- 이분법을 명시적으로 금지한다: "어느 하나가 오류인 게 아니라, **무엇이 주인공이냐에 따른 선택**."

→ 규격을 잠그는 이유가 **연출을 자유롭게 하기 위해서**다. 순서가 반대가 아니다.

## 사람이 남는 자리는 딱 하나 — 되돌릴 수 없는 것

- 유튜브 업로드·공개는 **절대 자동 금지.** 자가 루프의 최대치는 캘린더에 기록까지.
- 발행은 "올려" 한마디 후에만.
- 반대로 되돌릴 수 있는 건 **묻지 말고 하라**: "병목·오류는 명령을 기다리지 말고 알아서 처리한다 — 명령해서 듣는 건 시간낭비."
- "사용자 요청은 3종만: 발행 승인 / 키 발급 / 본진 복붙 한 줄. **왕복 1회 추가 = 실패 1회.**"

→ **되돌릴 수 있으면 실행, 되돌릴 수 없으면 사람.** 판단 비용을 이 기준 하나로 자른다.

## 문제를 사람이 아니라 상태로 본다

- "남 비판·자기 띄우기 금지. 문제는 **상태가 불완전한 것뿐**, 이렇게 하면 더 가볍게 될 수 있다는 **가능성**으로."
- 콘텐츠 톤 규칙처럼 보이지만, 시스템 판단에도 같은 형태로 나타난다 — 실수한 사람을 탓하지 않고 게이트가 없던 자리를 찾는다.
- → **톤 규칙과 시스템 규칙이 같은 뿌리에서 나온다.**

## 번복을 숨기지 않는다

판단이 뒤집힌 이력이 실제로 있다.

| 항목 | 경위 |
|---|---|
| 판정형 되묻기 | 07-20 유지 → 08-06 금지 |
| 흑백 vs warm_film | 07-17 컬러 → 07-18 흑백 재확정 → 08-04 이분법 금지 |
| Google Photos | 07-20 연동 계획 → 07-21 파이프라인에서 제외 |

- 뒤집을 때마다 **왜 뒤집는지 경위를 같이 남긴다.** ("오해 정정", "실측 결과")
- → 결론만 갈아끼우지 않는다. **판단의 이력이 자산**이라고 본다.

## 요약 — 다음 판단을 예측하는 기준

새 판단을 내려야 할 때 이 순서로 물으면 차노의 답에 가깝다.

1. 되돌릴 수 있나? → 있으면 그냥 한다. 없으면 차노에게.
2. 원본이 있나? → 없으면 만들지 말고 요청한다.
3. 실측했나? → 안 했으면 말하지 않는다.
4. 다음에도 되나? → 안 되면 배관부터 놓는다.
5. 이건 규격인가 감각인가? → 규격이면 잠그고, 감각이면 열어둔다.
6. 이 판단이 어디에 남나? → 남을 자리가 없으면 그건 아직 판단이 아니다.
