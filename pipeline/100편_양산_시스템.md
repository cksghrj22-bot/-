# 100편 양산 시스템 (무한 가동 엔진)

> 이찬호: "시스템 만들어서 100개 양산 가자." 프로젝트 목적 = 무한 컨텐츠 양성·무한 가동. 손으로 한 편씩이 아니라 **엔진이 100편 규모를 돌린다.** 설계는 100 규모로, 가동은 안정성 게이트로 램프업.

## 램프업 (안정성이 규모의 전제)
`5/일 실증 → 20 → 100`. 각 단계는 **앞 단계가 무인으로 안 멈추고 돌 때만** 올린다.
- 오늘(8/4) 실증: 3편도 실행이 멈추면 하루 날린다. 안 멈추는 파이프(watcher·인증·클론정리)부터 굳히고 규모를 올린다. 안 굳은 채 100 걸면 100편이 다 꼬인다.

## 파이프라인 6단계 (전부 비동기·트렁크 경유)
1. **씨앗 엔진 (100 주제 자동)**
   - 소스: 차노 구술 원본·재정의 카드·키워드 지도(내부) + 외부 고성과(조회수·시청시간 기준) 폼(클로닝 대상).
   - 조합엔진(`prompts/01_조합엔진`): **검증된 폼 × 차노 재정의 = 새 조합.** 100 주제 자동 생성.
   - **dedup 최우선**: 발행·예약·트렁크 대조. 규모 커질수록 중복 리스크 최대 → 이미 나간 씨앗 폐기.
   - 결 비율 헤어:마인드 2:1, **폼 다양성**(흑백/컬러/옴니버스/딕셔너리…)으로 100편이 똑같아 보이지 않게.
2. **브리프 (Cowork, 경량)**
   - 씨앗마다 훅 1줄·재정의 근거·2줄자막 방향·폼·B롤 지정. Codex가 이것만 보고 대본을 뽑게. Cowork는 완성 대본 안 씀(토큰).
3. **생성 양산 (Codex, 별도 quota)**
   - 브리프→대본 대량 생성. Cowork 토큰 안 씀.
4. **렌더 (watcher→Codex, 병렬)**
   - **렌더 전 체크리스트 자동 통과분만** 렌더(세그먼트≤26자·길이≥24s·B롤 다양성·아웃트로). 병렬 렌더로 throughput. 큐 관리(대기→완료).
5. **검수 at scale**
   - 자동(전량): `verify_render` + 줄수 검사.
   - 사람눈: 100편 다 못 보니 **컨택트시트 배치 + 샘플 판정 + verify PASS 자동통과.** Cowork는 이상치만 집어냄.
6. **예약 버퍼**
   - 통과분 비공개+publishAt로 며칠~몇 주 앞서 슬롯 분산. 형은 **veto만**.

## 스케일 장치
- **병렬 렌더 / 큐 / 재시도.** watcher가 안 멈추게 에러 핸들링·자가진단·알림(8/4 학습).
- **스토리지**: git엔 프리뷰(컨택트시트)만, 영상은 드라이브 `_최신_바로보기/`.
- **토큰/비용**: 생성·렌더 전부 Codex quota. Cowork는 브리프·판정만(`토큰_경제_규약`).
- **지연**: `지연_감축_로그`대로 버퍼-선렌더·TTS/B롤 캐시·병렬로 계속 깎음.

## 역할 (규모판)
- **Cowork** = 씨앗 선별·브리프·설계·이상치 판정·역제안(시장/브랜딩 방향).
- **Codex** = 대본 생성 + 렌더 양산.
- **watcher** = 유일 디스패처(중복 렌더 방지).
- **형** = 창의 방향 + veto.

## 다음 실제 스텝
1. 오늘 3편 파이프 안정 확인(watcher 무인 렌더 성공).
2. 씨앗 엔진으로 20 주제 배치 → 20편 무인 렌더·예약 실증.
3. 안정되면 조합엔진 폭 넓혀 100 주제 → 100편 버퍼. 각 단계 병목은 `지연_감축_로그`에 append.
