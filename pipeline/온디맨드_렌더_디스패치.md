# 온디맨드 렌더 디스패치 (다시는 수동 붙여넣기·내일 대기 없게)

> 2026-08-04 차노: "코워크에서 명령 → 코드방이 판단해 주문 → 코덱스가 실행 → 여기 띄움 → 피드백·수정 → 내가 최종결정. 이 간단한 걸 몇 번을 낭비하냐." + "여기서(코워크) 바로 뽑으면 코덱스 연동이 무의미. **코덱스가 렌더한다. 코워크는 아니다.**" + "이 문제 다시 안 터지게 고쳐서 레포에 커밋해."

## 무엇이 문제였나 (박제 — 재발 금지)
걸려 있던 자동 트리거가 **새벽 3시(UTC 18:00) 밤샘 오케스트레이션 하나뿐**이었다. 그건 **생성·지시서·더블체크용(Cowork 뇌 세션)** 이지 렌더가 아니다. 그래서 낮에 디렉터(Cowork)가 재렌더를 판정해도 **자동으로 실행할 렌더 경로가 없어서**, 형이 코드방에 수동으로 붙여넣거나 새벽까지 기다려야 했다 = 시간 낭비. 이게 근본 원인.

## 고정 원칙
- **렌더 = Codex Pro (별도 quota).** Cowork는 렌더하지 않는다(코덱스 자동화 우회 금지).
- **Cowork = 디렉터**: 명령·판정·컨택트시트 띄우기. 렌더 안 함.
- **코드방 = 디스패처/커밋**: 코덱스에 렌더 주문(`codex exec`), 결과 커밋·push. (샌드박스 밖 1회, claim 락 없음)
- **형 = 최종결정**: 통과본 발행 yes/no.

## 두 레인 (형이 정한 구조)
### 🌞 낮/온디맨드 레인 = 일반 코드방 (실시간)
1. **Cowork**가 판정 후 `content/shorts/<날짜>/_RENDER_JOB.md`에 잡을 `status: 대기`로 커밋·push. (통과표 포함)
2. **일반 코드방(상시 감시 루프)** 이 트렁크를 폴링하다 `status: 대기`를 보면 즉시:
   - `git pull --rebase` → `status: 진행중`으로 바꾸지 않아도 됨(렌더러 하나, 레이스 없음)
   - `codex exec`로 렌더 주문(통과표대로) → Codex가 파일(mp4·컨택트시트)만 생성
   - 코드방이 **샌드박스 밖에서 커밋·push** (`outputs/.../contact/*.png` + `_RENDER_JOB.md`에 결과 append, `status: 완료`)
3. **Cowork**가 완료 감지 → 컨택트시트 pull → 감독에게 띄우고 판정 → 형 최종결정.
   → **어느 단계도 형의 수동 붙여넣기 없음.** 형은 창의 명령과 최종 yes/no만.

### 🌙 밤샘 레인 = 3시 트리거 (배치 전용)
- `밤샘 오케스트레이션`(cron `0 18 * * *`)은 **대량 생성·지시서·아침 브리핑 전용**. 렌더 트리거 아님.
- 백업: 이 트리거가 돌 때 렌더 큐에 `대기` 잡이 남아 있으면 한 번 쓸어 렌더 주문까지 해준다(낮에 못 흐른 게 있으면 새벽에 처리).

## 코드방 상시 감시 루프 (한 번만 켜두면 됨)
일반 코드방에서 아래를 돌려두면 온디맨드 레인이 자동으로 흐른다(폴링 2~3분):
```
while true; do
  git -C ~/atnown-repo pull --rebase origin main -q
  # _RENDER_JOB.md 에 'status: 대기' 잡 있으면:
  #   codex exec <통과표대로 재렌더> → 컨택트시트 생성
  #   git add outputs/.../contact _RENDER_JOB.md && git commit && git push
  #   (status: 완료 로 갱신)
  sleep 150
done
```
- push 인증은 remote에 토큰 심어 headless(→ `pipeline/렌더_레이스_방지.md`).
- 이 루프는 **일반 코드방에서 한 번 시작**하면 낮 온디맨드가 계속 자동. 밤샘은 3시 트리거가 따로.

## 재발 방지 체크
- 렌더 잡을 낼 때 Cowork는 반드시 `status: 대기`를 명시(코드방 루프의 트리거 키).
- 낮에 렌더가 필요한데 30분 내 `완료`가 안 뜨면 = **감시 루프가 꺼진 것** → 코드방 루프 재기동(형에게 한 줄 알림). "새벽까지 기다려"는 답이 아니다.
