# 렌더 레이스 방지 + 단일 렌더러 규약

> 사건(2026-08-04): 두피·둥근 2편을 **Codex가 렌더+유튜브 예약(cc5c0c0, 8/5 11·16시)** 한 뒤, **코드방 Nightly 루틴이 같은 잡을 또 렌더**(중복). 원인 = ①렌더러가 둘 ②잡에 '점유(claim)' 표시가 없어 둘 다 pending으로 봄.

## 원인 분석
- **렌더러 2개 동시 존재**: Codex Pro + 코드방 Nightly 루틴. 둘 다 트렁크의 _RENDER_JOB을 보고 렌더 → 같은 걸 두 번.
- **락 없음**: 먼저 시작한 쪽이 '진행중'을 안 남겨서, 늦게 pull한 쪽도 pending으로 착각.
- **발행 게이트 침범**: Codex가 시안을 넘어 **유튜브 예약까지 자동**으로 걸음(감독 승인 전).

## 픽스 1 — 렌더러는 하나 (Codex)
- **렌더 담당 = Codex Pro 하나.** 별도 quota(Claude 토큰 절약) + 이미 작동.
- **코드방 Nightly 루틴의 '렌더' 역할 OFF.** (레이스·Claude 토큰 낭비 방지) 코드방은 렌더 말고 딴 역할만.

## 픽스 2 — 점유(claim) 락
렌더 착수 전 필수:
1. `git pull` (최신 확인) + `상황판.md`·완료보고 먼저 읽기.
2. 잡 상태를 `_RENDER_JOB.md`에 **진행중(에이전트·UTC시각)** 로 기록하고 **즉시 commit+push.**
3. 다른 에이전트는 상태가 진행중/완료면 **skip.**
4. 완료 시 상태=완료로 갱신+push.

## 픽스 3 — 발행 게이트 복구
- 렌더러는 **시안(mp4)까지만.** 유튜브/인스타 예약은 **감독 판정 후에만.**
- 자동 예약 금지. (이번 8/5 예약본은 감독이 정본 확인 후 유지/취소 결정.)
