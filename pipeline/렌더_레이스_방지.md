# 렌더 레이스 방지 + 단일 렌더러 + 커밋 경로 규약

> 사건(2026-08-04): ①두피·둥근 2편을 Codex가 렌더+유튜브 예약(cc5c0c0)한 뒤 코드방 Nightly가 같은 잡을 또 렌더(중복). ②이후 Codex `codex exec` 샌드박스가 `.git` 쓰기를 막아 claim 커밋이 실패 → 렌더 결과가 트렁크에 안 올라옴.

## 원인 분석
- **렌더러 2개 동시 존재**: Codex Pro + 코드방 Nightly. 둘 다 _RENDER_JOB을 보고 렌더 → 두 번.
- **claim 락이 오히려 걸림돌**: 렌더 착수 전 `.git` commit+push를 요구했는데, Codex `codex exec`는 샌드박스라 `.git` 쓰기 자체가 막힘 → claim 못 함 → 결과도 못 올림.
- **발행 게이트 침범**: Codex가 시안을 넘어 유튜브 예약까지 자동으로 걸음.

## 픽스 1 — 렌더러는 하나 (Codex)
- **렌더 담당 = Codex Pro 하나.** 별도 quota(Claude 토큰 절약) + 이미 작동.
- **코드방 Nightly의 '렌더' 역할 OFF.** 코드방은 렌더 말고 트리거·게이트·커밋만.

## 픽스 2 — claim 락 폐기 (레이스가 구조적으로 없음)
- 렌더러가 **하나**라 두 에이전트가 같은 잡을 동시에 잡을 일이 없음 → **claim 커밋 불필요.**
- 따라서 **렌더 착수 전 `.git` 쓰기(진행중 표시 커밋) 요구를 삭제.** 이게 샌드박스 블로커의 원인이었음.
- 상태 표기는 파일 텍스트(status: 대기/진행중/완료)로만 남기고, 커밋은 아래 커밋 경로에서 한 번만.

## 픽스 3 — 커밋 경로 (샌드박스 밖에서 한 번)
- **Codex(codex exec, 샌드박스) = 렌더만.** mp4·컨택트시트 PNG 파일 생성까지. **`.git` 건드리지 않는다.**
- **커밋·push = 샌드박스 밖 한 곳에서.** 우선순위:
  1. **코드방(나이틀리방) 일반 셸** — `codex exec` 밖. `git add outputs/... content/...` → commit → push. (권장, git 로그인 살아있음)
  2. 안 되면 **Codex 일반 모드**(대화형, 샌드박스 아님)에서 커밋.
- 즉, **렌더 끝난 파일만 샌드박스 밖으로 넘겨받아 커밋한다.** 샌드박스 안에서 커밋 시도 금지(어차피 막힘).
- 컨택트시트 PNG(작은 것)만 트렁크에 커밋 → Cowork가 pull해서 미리보기. full mp4는 드라이브.
