2. **잡이 `_done`으로 순간이동** — D방이 넣은 `TASK_010_011_backlog.json`(01:08Z)·`TASK_012_naver_draft_save.json`(01:07Z)이 생성 직후 `_done/`(1c5GZ73bP9FnWAVxz084-eDt5XjV6Y3ZW)으로 옮겨져 있음. **그런데 실행은 안 됨**(형: TASK_001~012 전건 무응답).
3. **`_status.txt`가 모순을 보여줌**:
   ```

   pulled: 0
   queue: 5 ['probe_longface.json', 'plan5.json', '_HEARTBEAT_본진.json', 'planC01.json', 'TASK03_thumb_smoke.json']
   ```

4. **하트비트 파일도 계속 `_done`으로 아카이브됨**(수백 개 쌓임) — 이동 로직이 "json이면 무조건 _done" 수준으로 무차별 동작 중이라는 방증.
5. `JOB-*.sh`(8/10)·`내일발행_숱치기_본문.txt`·`PUSH_*.b64`는 인박스 루트에 **그대로 방치** — .sh/.txt는 아예 안 집음.

## 원인 판정

**codex_watch.sh(또는 그 안의 드라이브 폴링부)가 "다운로드→로컬 큐 적재→실행" 전에 "드라이브 _done 이동"을 먼저(또는 무조건) 수행.** 다운로드/적재가 실패해도(파일명 패턴 불일치·로컬 경로 불일치·예외) 드라이브에서는 이미 사라진 상태 → 잡이 조용히 증발. 로컬 큐가 옛 파일 5개에서 안 바뀌는 것도 적재부가 죽어있다는 뜻.
(8/7의 codex 캐싱 버그와 같은 병: **로그·이동은 되는데 실체 실행이 없는 두 겹 거짓 신호.** 이번엔 "이동=처리됨"이 거짓 신호다.)

## 수리 순서 (본진 Cowork 실행)

1. `codex_watch.sh` 드라이브 폴링부에서 **순서 반전**: ①다운로드 ②로컬 큐 적재 성공 확인 ③그 다음에만 드라이브 `_done` 이동. 실패 시 드라이브에 남기고 `_status.txt`에 `pull_fail: <파일명> <사유>` 기록.
2. 하트비트/status 파일은 이동 대상에서 **제외**(이름 필터 `_HEARTBEAT*`, `_status*`).
3. 로컬 큐 정체분(probe_longface.json 등 5개) 처리 or 비우고, 적재 경로가 실행기(코덱스)가 읽는 경로와 **같은지** 확인(폴더통합 P3 경로 불일치 의심).
4. 수리 후 `_done`에서 **재투입**: `TASK_010_011_backlog.json` · `TASK_012_naver_draft_save.json` → 인박스 루트로 되돌려 실행. (TASK_012는 형이 수동 스크립트로 오늘분 처리했으면 임시저장 중복만 주의 — publish:false라 안전.)
5. 검증: 더미 `TASK_TEST_ping.json` 넣고 → _status에 `pulled: 1` + 로컬 큐 반영 + 실행 응답까지 확인되면 완료. 결과를 이 파일 하단에 append.
