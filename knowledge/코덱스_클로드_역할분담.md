# 코덱스 ↔ 클로드 역할분담 (2026-08-03 이찬호 지시로 박제)

> 한 줄 규칙: **생각·글·코드 = 클로드에서 끝내고 리포에 커밋. 렌더·업로드 = 코덱스가 pull 받아 실행.**
> 둘은 경쟁이 아니라 **두뇌(클로드) ↔ 손(코덱스)**. 리포가 둘 사이 다리다.

## 왜 이렇게 나누나
코덱스가 클로드보다 느리다. 그런데 **로컬 실행(ffmpeg 렌더·드라이브 파일·유튜브/인스타 업로드)은 영상과 인증이 있는 맥에서만** 된다.
그래서 느린 걸 억지로 빠르게 만들 게 아니라, **각자 잘하는 데만** 쓴다. 그러면 코덱스가 느려도 문제가 안 된다(걘 백그라운드로 "실행만" 하니까).

## 역할표
| | 클로드 (클라우드 코드방) | 코덱스 (맥 로컬) |
|---|---|---|
| 위치 | 클라우드, 리포만 봄 | 네 맥 = 영상·드라이브·인증 다 있음 |
| 속도 | 빠름 | 느림 (근데 로컬 실행은 여기서만 됨) |
| 시킬 것 | 기획·서사·대본·캡션·카드 텍스트·**코드 작성/수정**·매니페스트 JSON·판단·반복작업(초안 여러 개·자가비평) | **렌더(shorts.cardposter/render)·업로드·드라이브 파일 이동** |
| 시키지 말 것 | ffmpeg 렌더·드라이브·업로드 (이 세션은 해당 MCP 없음) | 애매한 기획·글쓰기 (헤매서 더 느려짐) |

## 표준 파이프라인 (3단계)
1. **클로드(빠름)** — 대본·캡션·카드 텍스트·매니페스트 JSON·렌더 코드까지 다 짜서 **리포에 커밋**
   (글쓰기는 항상 `prompts/00_차노화_마스터.md` + `knowledge/차노_보이스.md` 규약 거친다).
2. **코덱스(로컬)** — `git pull` → `python3 -m shorts.cardposter/render`로 **렌더** → 드라이브 `앳나운_영상/_최신_바로보기/`에 올려 **시안 링크**.
3. **형 승인** → 코덱스가 **업로드**(유튜브/인스타). 발행·외부액션은 승인 후에만.

## 코덱스 느림 줄이는 3가지
1. **리포를 iCloud 밖으로.** iCloud 동기화 폴더(`~/Documents/…`) 안에 리포가 있으면 `.git` 객체가 클라우드 placeholder로 방출돼 git 명령마다 90초씩 멈춘다.
   → `~/atnown-repo`처럼 홈폴더(동기화 안 되는 곳)에 두면 git이 순식간. (2026-08-03 실증: `~/Documents/Codex/repo` → `~/atnown-repo` 이동 후 `git status` 0.02초.)
2. **코덱스한텐 "정해진 실행"만.** "이 매니페스트로 렌더해서 올려" ✅ / "긴얼굴 콘텐츠 기획해줘" ❌. 애매한 건 클로드가 먼저 확정.
3. **병렬로 굴린다.** 클로드가 다음 편 대본 쓰는 동안 코덱스가 이전 편 렌더 → 기다리는 시간이 사라진다.

## 형이 판단할 건 딱 둘
① 어떤 콘텐츠 ② 시안 OK / 발행 승인. 나머진 자동으로 흐르게 둔다.

## 단일 줄기 규약과의 경계
- 실서비스 브리핑·예약 자동화·Creator OS는 **본진(맥스튜디오) 전담** — 여기서 생성 금지(허브 「🌳 단일 줄기 규약」).
- 코덱스↔클로드 분담은 그 아래 "제작 실행" 레이어의 규칙이다. 발행은 항상 형 승인 후.

## 🔌 인계 장치 — 렌더 트리거 (2026-08-04 이찬호 지시로 신설)

**"클로드는 밤샘 트리거, 코덱스가 이어받아 렌더."** 클로드가 직접 ffmpeg를 돌리면 분담 위반이고
방 충돌이 난다 — 2026-08-04에 실제로 같은 잡을 두 방이 병렬 렌더한 사고가 났다.

    python3 scripts/render_trigger.py             # 대기건 목록만
    python3 scripts/render_trigger.py --dispatch  # 코덱스에게 인계

- **대기 판정 = `pipeline/렌더_레이스_방지.md` 규약의 `status:` 표기.** `_RENDER_JOB.md` 안에
  `status: 대기` 가 남아 있으면 대기, `진행중`/`완료`면 skip. 점유(claim) 락은 코덱스가 잡는다
  (착수 시 status→진행중 commit+push, 완료 시 →완료). 트리거는 락을 대신 잡지 않는다.
  ⚠️ 파일 단위 '완료 마커'는 쓰지 않는다 — 한 파일에 잡이 여러 번 append 되므로 새 잡이 밑에 붙었는데
  위쪽 마커 때문에 건너뛰는 사고가 난다(2026-08-04 실증).
- 코덱스 CLI 경로 = `/Applications/ChatGPT.app/Contents/Resources/codex` (ChatGPT 앱 번들 안. `which codex`엔 안 잡힘).
  다른 경로면 `CODEX_BIN` 환경변수로 덮어쓴다. 작업 클론 = `~/atnown-repo` (`CODEX_CWD`).
- 트리거가 코덱스에게 주는 프롬프트에 **발행·예약 금지**가 박혀 있다(감독 프리뷰 게이트). 시안까지만.
- 코덱스에겐 렌더 시작 전 `git pull --rebase` 후 "이미 완료 보고가 있으면 손대지 말고 종료"를 먼저 시킨다 — 중복 재발 방지.
