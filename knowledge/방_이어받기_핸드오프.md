# 🔄 방 이어받기 핸드오프 — 렌더 파이프라인 (2026-08-06)

> 방이 멈추면 이 프롬프트를 새 방(코워크/코드방)에 그대로 붙여넣어 이어받는다. 채팅기억 0이어도 리포가 공유기억.
> 재사용: 상태 부분만 최신으로 갱신하고 붙여넣으면 된다.

---

```
[방 이어받기 — 렌더 파이프라인 핸드오프]

너는 AT NOWN 코드방/코워크다. 앞선 방이 멈춰서 네가 이어받는다. 채팅기억은 0이지만
리포가 공유기억이다. 아래 순서로 복원하고 "재질문·재승인 없이" 바로 이어서 진행하라.

■ 먼저 읽기 (정본 로드)
1. ~/atnown-repo 에서: git pull --rebase origin main
2. CLAUDE.md · AGENTS.md · knowledge/결정사항_대장.md · 상황판.md
3. _본진_핸드오프_push수리.md · content/shorts/2026-08-04/_RENDER_JOB.md 끝부분

■ 현재 상태 (직전 방이 여기까지 함)
- 시안 PASS 완료·로컬 정체: 01 두피자외선 / 02 둥근얼굴단발 / 04 재현=방향 / 06 작심삼일.
  → 파일이 ~/atnown-repo/outputs/2026-08-04_render_job/final/ (및 _current/) 에 로컬로만 있음.
  → 드라이브 _최신_바로보기 업로드 실패(CloudStorage 'Operation not permitted') = 미전달.
- watcher(scripts/render_watch.sh) git push 만성실패 = 원인 규명됨: HTTP/2 sideband 오류(인증 아님).
- 매니페스트 팔레트 8형 존재(56c34fb). 렌더 큐 = content/shorts/*/_RENDER_JOB.md (status:대기), render_trigger.py가 읽음.

■ 지금 이어서 할 일 (우선순위)
1. watcher push 수리: ~/atnown-repo 에서 →
     git config http.version HTTP/1.1 ; git config http.postBuffer 524288000
   그다음 밀려있던 watcher 커밋 1사이클 정상 push 확인.
2. 시안 전달: PASS 4편 mp4를 로컬 outputs 폴더에서 꺼내 형에게 파일로 전달(드라이브 우회) 또는 Drive 업로드 복구.
3. 중복 렌더 충돌(04·06 3회 렌더): 조치안 A(나이틀리 dispatch 삭제, watcher 단일 디스패처) — 감독 판정 대기건. 형 판정 없으면 손대지 말고 보고만.

■ 가드레일 (불가침)
- 발행·예약 자동 절대 금지 = 감독 프리뷰 게이트. 시안까지만.
- 렌더 큐는 _RENDER_JOB.md 하나. 새 큐(_jobs/ 등) 만들지 마라(충돌).
- 커밋마다 git pull --rebase 후 push. 콘텐츠 임의 생성·변경 금지(학습 #13).
- 연결구조 = 본진 하나·길 셋(코워크/디스코드/코드방 독립경로). 체인 아님.

끝나면 한 줄 요약 + _RENDER_JOB.md에 결과 되쓰기(영수증).
```

## 사용법
- 방 멈춤 감지 → 이 파일 열어 위 코드블록 복사 → 새 방에 붙여넣기.
- 「현재 상태」·「지금 이어서 할 일」은 그때그때 최신으로 갱신 후 넘긴다(핵심은 리포가 정본이라 새 방이 스스로 최신을 pull함).
