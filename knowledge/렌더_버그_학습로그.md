# 🐞 렌더 버그 학습로그 — 같은 원인 두 번 안 겪는다 (2026-07-16)

> 이찬호 지시: "원인을 자꾸 학습해야 될 거 아니야." 여기 적힌 건 **코드로 이미 고쳐졌고**, 증상→원인→수정을 남겨 다음 세션이 재발 안 시킨다.

## 1. BGM이 조용히 사라짐 (가장 오래 헤맴)
- **증상**: `--bgm`을 줬는데 영상에 음악이 없음. 에러도 없음(조용한 무음).
- **진짜 원인**: `shorts/proof.py`가 `probe_duration`을 **import 안 함** → `_valid_bgm()` 안에서 `probe_duration(path)` 호출이 **NameError** → `except`로 잡혀 **무조건 False** → `bgm_pool`이 유효 BGM을 버림 → 렌더는 음악 없이 진행.
- **수정**: `from .render import render, probe_duration` (import 추가). + `probe_duration`을 ffprobe 실패 시 ffmpeg 파싱 폴백(간헐 실패 방어). + `render_batch`에 "BGM 못 읽으면 경고" 추가(조용한 무음 방지).

## 5. 교보손글씨가 또 나눔으로 뒤바뀜 + 검사기가 틀린 폰트를 통과시킴 (2026-07-16 재발)

  - (a) config가 어느 시점에 Kyobo→Nanum으로 조용히 바뀜(근거 없는 재유추).
  - (b) 검사기가 **`NanumSquareRound`가 있어야 통과**하도록 짜여 있어 틀린 폰트를 정답으로 알고 통과시킴.

## 8. 긴 BGM 정중앙(이음매)이 무음 — 짧은 편만 아웃트로 BGM FAIL (2026-07-20)
- **증상**: 같은 긴 BGM으로 11(45초 나레이션)은 통과, 13(29초 나레이션)은 아웃트로 RMS **-50~-51dB**로 두 번 연속 FAIL. B롤 스타트를 바꿔도(오디오 무관) 동일. "플레이크"로 오해했으나 **결정적**.

- **진짜 원인**: Google Drive가 **큰 바이너리(특히 영상)를 '위험할 수 있음(abuse)'으로 flag** → 다운로드 시 `acknowledgeAbuse=true` 파라미터 필수. 없으면 무조건 403(quota와 무관·바이트 수 무관).
- **해결**: `shorts/drive_stream.py` MEDIA_URL에 `&acknowledgeAbuse=true` 영구 추가 → 모든 footage 다운로드에 자동 적용. 정밀진단(Range bytes=0-1023 단일요청)으로 200/206 확인.
- **교훈**: 403을 무작정 quota로 보고 두드리면 rate-limit까지 부른다. 원인 진단(단일 요청+에러바디 확인) 먼저. drive.readonly 스코프면 파일ID로 어떤 파일이든 받는다(MCP 승인 불요).

## Drive 접근 = 우회 말고 시스템으로 예방 (2026-08-01 형 '우회하면 같은 문제로 또 걸려·문제를 예측하며 일하라')
- **잘못**: 403 만날 때마다 우회(acknowledgeAbuse→청크→사본)로 때움 → 같은 root(재다운·하드호출)로 rate-limit·quota 재발. 문제 만들어놓고 '식을 때까지 대기'로 형을 멈춰세움.
- **근본 예방(drive_stream.py 재설계)**: ①`ensure_cached`=파일을 세션캐시(/tmp/drive_cache)에 **딱 1회** 통다운·재사용(같은 파일 두 번 안 받음→quota 예방) ②`_throttle_wait`=모든 Drive 요청 최소 1.2s 간격 ③`_get_bytes`=403/429 지수 백오프(6·12·24·48·90s) ④extract는 캐시에서 로컬 추출(ffmpeg가 Drive 직접 안 두드림→abuse/quota/rate 근절) ⑤초대형(>400MB)만 스트리밍 유지.
- **교훈**: 외부 API는 '요청을 아끼는 설계'가 먼저(캐시·throttle·백오프). 우회는 증상, 캐시는 원인. 문제를 만난 뒤가 아니라 만들기 전에 막는다.


## 일레븐랩스 401 = 인증/권한 아니라 크레딧 소진 · 무음 영상 4편의 진짜 원인 (2026-08-09)
- **증상**: STT가 계속 401. 권한 패널에서 「음성 텍스트 변환」을 허용해도 그대로 401. 새 키를 만들어도 401.
  같은 시기 렌더된 12편 중 4편(S1_v2·S7_v2·SEED5·YS_v3)의 오디오에 나레이션이 통째로 없었다(BGM만).
- **오진**: 며칠간 키 권한 문제로 보고 키 재발급·권한 토글·키 교체를 반복했다. 형 손을 두 번 빌렸다.
- **진짜 원인**: 일레븐랩스는 크레딧 소진을 HTTP 401로 돌려준다.
  `401 {"code":"quota_exceeded","message":"You have 0 credits remaining, while 4 credits are required"}`
  /v1/voices·/v1/models 는 200(무과금), TTS·STT만 401 → 인증은 멀쩡했다.
  **판별법**: 에러 바디의 code를 본다. quota_exceeded면 잔액, missing_permissions면 권한.
  "필요 크레딧 N"을 계산해 돌려줬다는 것 자체가 권한은 통과했다는 증거다.
- **연쇄 사고**: 렌더 도중 크레딧이 0이 되자 TTS가 401을 뱉었는데, 파이프라인이 실패로 처리하지 않고
  보이스 없이 BGM만으로 렌더를 계속했다. 이걸 잡을 read_ok 게이트는 같은 401로 죽어 있었다.
  **검사 도구와 생산 도구가 같은 자원에 묶여 있으면 동시에 죽는다.**
- **해결 3종**: ①TTS 실패 하드 스톱(200 아니면 중단, 1000바이트 미만 실패, 보이스 총길이 0.5초 미만 중단)
  ②TTS 캐시 `_tts_cache/<sha256(text+voice_id+model_id+settings)>.mp3` — 131,000자를 태운 건 편이 많아서가
  아니라 같은 문장을 재렌더마다 다시 만들어서다(12편 본문 합계 3,600자 = 36회 재생성분)
  ③듣기 게이트를 로컬 faster-whisper로 분리 — voice_present_ok: 세그먼트 0이면 즉시 FAIL.
- **무음 판별 실측법**: `ffmpeg -lavfi showspectrumpic` 로 스펙트로그램을 그려 눈으로 본다.
  정상 = 16kHz까지 음절 단위 세로 줄무늬가 빽빽. 무음(BGM만) = 5kHz 이하 매끄러운 저역 띠뿐.
  볼륨(mean_volume)은 BGM 때문에 정상으로 보이므로 레벨만 보면 못 잡는다.
- **정확도 실측**: 같은 오디오에 대해 일레븐랩스 scribe_v1은 "웨이브 올해 가계 세게"로 3곳 오독,
  로컬 whisper small은 정확히 전사. 검수는 로컬이 정본이고 유료 STT는 안 쓴다.
- **교훈**: ①에러 코드를 읽어라 — HTTP 상태만 보면 오진한다 ②외부 API 실패는 조용히 넘어가면 안 된다,
  그 자리에서 멈춰야 한다 ③검사 경로와 생산 경로는 다른 자원 위에 둔다 ④재사용 가능한 유료 산출물은 캐시한다.

## 2026-08-14 stash 복구 — reset 사고 후속 조치

### 상황
- 17:44:14 `git reset origin/main` 실행으로 untracked 파일 소실

### stash 구조
```
stash@{N}      = WIP (staged + working)
stash@{N}^2    = index (staged only)  
stash@{N}^3    = untracked files
```

### 복구 명령
```bash
# 전체 확인
git stash list
git stash show stash@{N} --name-only

# untracked 파일 확인
git show --stat stash@{N}^3

# 특정 폴더만 추출
git checkout stash@{N}^3 -- "_jobs/_done/_review/"
```

### 교훈
- reset 전에 stash가 있었으면 복구 가능
- untracked 파일은 ^3 커밋에 있음
- **reset --hard 금지가 규칙인 이유가 이것**
